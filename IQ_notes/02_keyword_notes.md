# Keywords — Source Code vs Bytecode vs Binary Code

## Three Layers of Code Execution

| Keyword | Meaning |
|---------|---------|
| **Source Code** | High-level text written by a developer in a `.js` file. Human-readable, platform-independent. |
| **Bytecode** | Intermediate instructions generated by V8's Ignition interpreter after parsing. Partially readable (mnemonics), platform-independent (runs on V8 VM). |
| **Binary Code** | Raw machine instructions the CPU executes. Not human-readable (hex bytes), platform-dependent (x64, ARM, etc.). |

---

## Bytecode Mnemonics (V8 Ignition)

| Keyword | Meaning |
|---------|---------|
| **GetNamedProperty** | Look up a property on an object (e.g., `console` or `.log`) |
| **LdaConstant** | Load a constant value from the constant pool |
| **Star0 / Star8** | Store the accumulator value into a register |
| **CallUndefinedReceiver1** | Call a function with one argument and no `this` binding |
| **Return** | Return from the current function |

---

## Key Comparison Aspects

| Keyword | Meaning |
|---------|---------|
| **Who writes it** | Source Code → Developer; Bytecode → V8 compiler; Binary Code → TurboFan JIT |
| **Storage** | Source Code → `.js` file; Bytecode → Memory (V8 heap); Binary Code → Memory (V8 code space) |
| **Speed** | Source Code → N/A (not executed); Bytecode → Slower (interpreted); Binary Code → Fastest (native CPU) |
| **Size** | Source Code → Small (~1 line); Bytecode → ~119 bytes; Binary Code → ~600 bytes |
| **Optimization** | Source Code → None; Bytecode → Minimal; Binary Code → Highly optimized |
| **Debugging** | Source Code → Easy; Bytecode → Hard; Binary Code → Very hard |

---

## Execution Pipeline Keywords

| Keyword | Meaning |
|---------|---------|
| **Parser** | Converts source code into an Abstract Syntax Tree (AST) |
| **AST (Abstract Syntax Tree)** | Tree representation of the code structure produced by the parser |
| **Ignition** | V8's fast interpreter that generates and runs bytecode |
| **TurboFan** | V8's optimizing JIT compiler that generates native machine code |
| **JIT Compilation** | Just-In-Time compilation — combines interpretation (fast startup) with native compilation (fast execution) |

---

## General Concepts

| Keyword | Meaning |
|---------|---------|
| **Human-readable** | Code that a developer can read and understand (Source Code ✅, Bytecode ⚠️, Binary ❌) |
| **Platform-independent** | Code that runs on any CPU architecture (Source Code ✅, Bytecode ✅) |
| **Platform-dependent** | Code tied to a specific CPU architecture (Binary Code ✅) |
| **x64** | 64-bit x86 architecture (Intel/AMD CPUs) |
| **ARM** | ARM architecture (mobile, Apple Silicon, Raspberry Pi) |
| **Hex bytes** | Hexadecimal representation of raw binary machine code |
| **Assembly mnemonics** | Human-readable abbreviations for CPU instructions (e.g., `movq`, `push`, `call`) |
| **V8** | Google's JavaScript engine used by Node.js and Chrome |
| **Hot code** | Frequently executed functions that trigger TurboFan JIT compilation |
